ImageGenCam

一台手持相机，保存的不是它看到的画面，而是 AI 重新想象出来的结果。 按下快门，照片带着选定的提示词发给图像模型，几秒后转换好的画面回到屏幕上。

项目 fork 自 openai/imagegencam （树莓派原版），并移植到 Orange Pi Zero 2。

  • 查看代码仓库
  • 全部项目

硬件

部件 说明
主板 Orange Pi Zero 2（全志 H616），Ubuntu Focal，4.9 旧内核
屏幕 320×480 SPI TFT（ST7796U / MSP3526），5 V，接在 SPI1 /dev/spidev1.1
摄像头 USB 摄像头（Sunplus 2M）焊在 13 针排针的 USB2 第 1 至 4 脚上，因为外壳没有开 USB-A 口
按键 1 个 MX 轴（快门）+ 4 个 6×6 mm 轻触开关，在屏幕右侧排成菱形
供电 5 V / 2800 mAh 单节 18650 电池 → SPDT 开关 → 配电洞洞板
闪光灯 热靴通过 PC11 上的 MOC3021 光耦可控硅驱动（电气隔离）

软件

纯 Python，没有用框架。一个多线程控制器负责屏幕、摄像头和 GPIO；标准库的 HTTP 服务器在同一块板子上提供手机端界面。

  • 5 个提示词预设，其中包括自定义的 毕业日 🎓，可以在手机上修改
  • 魔法模式：长按拍一张参考照片，让大模型据此写出新的提示词
  • 持久化任务队列：能扛过重启和断网，网络恢复后自动继续处理
  • 网页界面：带缓存缩略图的相册、多选打包下载、批量删除、Wi-Fi 切换，还有带五个虚拟按键的遥控页
  • 开机自启：systemd 服务跑在 80 端口，开机直接进入相机
  • 63 个测试，全部通过

在中国遇到的问题

项目基于 Vercel AI Gateway，而 Vercel、OpenAI 和 Google 都被防火墙挡住。为此做了两手准备：

  • china 分支：通过新增的 IMAGE_GEN_API=generations 模式接入 SiliconFlow（Qwen-Image-Edit + Qwen2.5-VL），魔法模式改用对话接口
  • 结果发现在目前所在地 Vercel 是通的，两个 API 测试在设备上都能通过

调试过程：真正出问题的地方

现象 原因
每个脚本都在 GPIO 上崩溃 libgpiod 在 4.9 内核上抛出 ValueError ，而自动回退没有捕获它。已修复并补上测试
脚本没读取 .env 硬件脚本一直没有加载它。已修复
屏幕亮着但没有画面 屏幕和主板没有共地，这才是当天真正的元凶
预览卡在 5 fps 每一帧被切成 75 次 Python 端 SPI 写入；现在只用一次 writebytes2，快了大约 3 倍
颜色反了 DISPLAY_INVERT=1
网页界面在 :8000 打不开 服务跑在 80 端口，只有手动启动才用 8000
